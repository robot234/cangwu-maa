# 商店兑换核对

适用于精英、后勤、联合、大师商店。正常任务默认先自动重新识别；`核对商店兑换.bat` 是无法自动判断时的人工入口，该工具本身不连接游戏、不点击确认，也不会重新兑换。

## 默认自动核对

再次正常运行商店任务时，助手会先检查上次待核对记录。它先等待上次请求稳定，再独立重新进入商店两次，只核对对应商品、币种、余额和库存，不在核对期间再次确认兑换。

- 库存减少的数量等于上次提交数量，且余额变化与总价一致：按已成交结案，补记**原记录周期**的目标数量，避免重复补兑这笔。
- 库存仍为原值，余额也未见扣款：按未成交结案，解除待核对，然后按当前目标和余额执行后续正常流程。买不起仍会跳过。
- 两次读取不稳定、网络／登录提示未消失、数据有冲突或无限库存等无法排除歧义：保留待核对，不重复提交，留待下一次重识别或人工处理。

旧版记录缺少数字时，会尝试用 Maa 重新读取原兑换预览图，也支持在迁移后从本目录的 `runtime/runs` 查找同一运行文件。缺失的历史信息不会被补造。

跨天不会一概转人工：新记录保存该商品的库存重置倒计时；倒计时能够证明库存尚未刷新时仍可自动核对。已经刷新、倒计时不够或原周期无法核实的情况不自动判定。核对跨过日／周目标周期时，只给原周期记账，再按新周期规则计算目标。

每次成功结案前都会备份原账本及核对截图，人工核对和自动核对有不同的来源标记。旧记录没有可靠提交时间时，第一次自动核对会额外等待约 30 秒，以免把还没结算的请求误判为失败。

## 余额不足

确认兑换前，助手会先识别余额旁的货币图标，再读取该币种的余额。余额不足时取消预览并跳过商品，不留下待核对记录。MAX 点击后仍停在默认 1 份时，不再把这个数字当作买得起的证明。

余额、币种未读清时停止。`K`、`M`、`万`、`亿` 是缩略显示，助手保守计算范围；正好处在价格边界、无法确认足够时也跳过。不会把另一种货币的余额或商品价格当成可用资金。

## 人工核对步骤

1. 停止日常任务，暂时不要手动兑换同一商品。
2. 双击程序目录里的 `核对商店兑换.bat`，选择被锁定的商店。
3. 查看商品、数量、总价、原记录周期及截图路径。对照**同一次兑换**前后的余额、商品剩余数量和奖励；单看今天买不起或换日后的库存，不能证明之前没有成交。
4. 只能确认全部成交时选 `1`；能确认完全未成交时选 `2`；不确定、疑似部分成交或证据缺失时选 `0`，保持锁定。
5. 填写人工核对依据和已核对的 PNG/JPEG 游戏截图完整路径。输入 `确认核对` 后才会更改记录。

解除前，工具会在 `runtime/state/reconciled` 中保存原文件的精确备份、核对截图副本和人工核对说明。已成交会计入**原记录周期**；未成交不会增加兑换数量。跨天或跨周核对不会给今天错误加次数，正常任务之后仍按原规则换日／换周。这个操作不开始任何新的兑换。

旧版待核对文件可以使用此入口，但旧版缺少的前后数字不会被补造。需要结合原运行目录里的预览、超时截图及游戏记录确认；没有充分依据就保持锁定。

## 新记录中的证据

- `before_balance`、`before_stock`：提交前对应币种的余额范围及商品库存。
- `before_stock_reset_days`、`before_device`：原商品库存重置倒计时和原设备，用于避免刷新或切换设备后的误判。
- `evidence`：提交前预览截图路径。
- `reward_evidence`：实际观察到的奖励截图；没有观察到时不填写。
- `after`：核对商品列表后的画面和能读到的余额、库存。
- `last_observation`：发生异常时最后观察到的画面。`fresh_since_submission=false` 表示没有取得比提交前更新的画面，不能把它当作事后证据。
- 数字或截图无法取得时会明确记录缺失原因，继续保持待核对；程序不会自动删除该记录重试。

成功兑换的核对信息保留在 `last_exchange`；人工核对说明通过 `last_resolution` 指向备份目录。请保留 `runtime/state` 和原 `runtime/runs`，不要通过删除账本来解锁。

## 从旧版自动更新

v0.4.10 及更早版本的更新器限制新增根目录入口。为兼容旧版，v0.4.11 更新包包含完整的余额检查和自动核对逻辑，但不新增 `核对商店兑换.bat` 与 `tools/reconcile_shop.py`；需要人工核对时可使用下方模块命令。下载完整包则同时提供双击入口。两种安装方式均不会自动删除旧账本。

## 命令行

仅查看，不修改：

```powershell
.\.venv\Scripts\python.exe -m cangwu.shop_review --shop elite
```

交互核对：

```powershell
.\.venv\Scripts\python.exe -m cangwu.shop_review --interactive
```

脚本提交需要同时填写 `--apply`、`--outcome`、`--note`、`--evidence` 和查看时的 `--expected-record` 指纹。记录变化、核对依据缺失、格式异常或备份失败时不解除。任务运行期间受同一设备锁保护，须先停止任务。

## 识别资源来源

余额图标裁自已有公开测试图的顶栏，不包含账号信息。`token` 使用 `exchange_arena_token.png` 的 `(872,28,901,58)`；`shield`、`logistics`、`union`、`master` 分别使用同名兑换测试图的 `(1056,28,1086,58)`。相同图标同时放入 `assets` 和 `app/resource/image`，供离线及 Maa 识别使用。

`exchange_elite_insufficient_balance.png` 是基于已有耀闪的残响预览图构造的回归测试图：将顶栏余额改为 2295、输入数量改为 1、总价改为 7500。它用于真实 Maa OCR／模板的离线回放，不是本次实机复现，也不是反馈者提交的原始截图。
