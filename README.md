# 苍雾世界 Maa 助手

基于官方 MXU 2.7.1 与 MaaFramework 5.14.3 的苍雾世界国服日常助手，适用于 Windows x64 和 MuMu 模拟器。

## 首次安装

先安装 **64位 Python 3.13** 和 MuMu，在模拟器中安装苍雾世界国服并设为横屏16:9。在项目目录打开 PowerShell，依次运行：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe tools\setup_runtime.py
```

安装脚本从官方来源下载固定版本的 MXU 与 Maa 设备辅助程序，并按 `DEPENDENCIES.json` 校验 SHA256；Maa原生库来自固定版本的Python依赖。不会修改任务配置、连接模拟器或执行游戏操作。需要网络访问GitHub和PyPI。

仓库包含源码、OCR模型和必要识别素材；运行库、个人配置、账号截图、日志、快捷方式及本机实测原始记录不上传。安装完成后双击 **启动苍雾助手.bat**。首次打开时选择MuMu设备及国服资源，再检查任务选项。设备地址不同可复制 `config.example.json` 为 `config.local.json` 后调整 `device.serial`。

已配置好的本机环境可直接使用；更新源码时保留 `.venv`、`app/config`、`config.local.json` 和 `runtime/state`，后者包含兑换进度与未确认交易记录。

## 怎么用

1. 双击项目根目录的 **启动苍雾助手.bat**；MuMu 尚未打开时，助手窗口也能正常打开。本机已有的同名快捷方式也可继续使用。
2. 打开 MuMu 的「国服」实例，进入苍雾世界大厅。助手界面打开后会搜索并尝试连接上次使用的设备；如果先开了助手，再开 MuMu，点击右侧「设备」旁的刷新按钮重新搜索。
3. 等右侧显示连接成功；勾选要做的任务，点击 **开始任务**。

默认执行指挥室收菜、远征检查与续派、邮件、好友、首页推荐免费礼包、活动扫荡、竞技场代理和任务／通行证领奖。

活动固定为你指定的 **闪耀之始-7**，每次 42 体力。展开活动卡片可设置保留体力；展开竞技场卡片可设置本轮用票上限；远征默认续派 12 小时。

远征支持「点击领取 → 再次派遣」的两队批量收取和续派，也能恢复停在「再次派遣」弹窗的任务。续派会核对任务名称和上次时长，沿用原队伍；弹窗时长与界面设置不一致时会停止，请先在游戏中调整一次。竞技场支持结算页的「确认／确定／刷新」按钮，等待加载结束后再确认。

任务奖励包含两部分：先领取列表的「一键领取」，再分别检查每日 100 积分、每周 90／150 积分、每月 150／300／450 积分的底部奖励。「一键领取」变灰后，仍会继续领取底部「可领取」的档位，并核对「已领取／已获取」状态。

**首页推荐 · 免费礼包** 已按你的要求默认勾选：进入「商城 → 首页推荐 → 通常礼包」，只领取名为“免费礼包”、列表及确认窗口消耗均为 **0** 的一份礼包；领取后核对奖励，以及礼包下架后的固定列表布局（或剩余数量归零）。已领取时跳过，不处理旁边的付费礼包。

### 自选商店兑换与装甲进阶

提供 **精英、后勤、联合、大师商店 · 自选兑换** 和 **装甲进阶 · 每周共鸣**。新任务及具体商品默认关闭；已有设置保留。展开后逐项打开需要的商品／共鸣开关，填写数量，再勾选任务并开始。调度商店已移除。

- 精英17项、后勤12项、联合9项、大师14项，均按实机商品、单价与货币列出；两个精英演习券版本分开设置，水晶还核对商品图。本期已售罄的商品仍可配置，执行时跳过。
- 每个商品填写 **目标份数（1～999）**。后勤是 **每周目标**，按周累计，周一北京时间05:00换周；其他商店保留每日目标，05:00换日。重复运行只补当前周期未完成的数量。
- 你填的数量超过库存或现有货币上限时，以游戏确认窗口的 **MAX** 为准。例如填999份、实际最多5份，就只兑5份；售罄或一份也换不起则跳过。不会补充货币。名称带 `*10`／`*100`／`*1000` 表示每份内含数量。
- 逆爱、索贝克、利维坦分别打开并设置 **每周目标次数（1～5）**，关闭即为 0，合计最多 **5 次**。装甲任务排在活动清体力之前，只扫荡本账号已通关的 **1-5 地狱（40 体力／次）**。游戏显示 **剩余 0/5** 时直接跳过，本周已经打满的状态已实机验证。
- 共鸣累计次数保存在本地。只有观察到游戏剩余次数增加才自动开始新的周记录；跨周但游戏计数没增加、且有旧执行记录时会要求核对，避免猜测后重复消耗。其他方式手动打过的次数，以游戏剩余总次数为上限。
- 每轮仍共用 20 分钟、200 次操作预算。大量商品／较大数量可能分轮完成，已成功核对的每日／每周进度会保留。

商品名称、货币和单价来自 2026-10-17 的实机。换商品、改价或界面识别不清时会停止，需更新清单。货币标签按各商店实际图标区分，不冒充官方资产名称。

提交前先写入待确认记录，再点一次确认。结算、奖励或库存变化未核对成功时，下一次会要求检查记录，**不会自动再兑／再扫**。记录在 `runtime/state`；不要直接删除待确认记录重跑，应先核对游戏和对应截图。完整清单见 [商店商品清单](docs/商店商品清单.md)。

停止：点界面的 **停止任务**，按 **F8**，或双击 **停止助手.bat**。停止后不会继续点击；游戏内已经开始的竞技场代理仍由游戏完成，下次可以领取结果。

只检查设备：双击 **仅检查连接.bat**，或者只勾选「仅检查连接和识别」。这个任务不点击游戏。

## 默认规则

- 只用现有体力和演习券，不买体力、不充值、不抽卡、不分解。勾选商店任务及具体商品后，允许用已有对应货币兑换，包括用户选择的精英演习券。
- 不取消运行中的远征。空闲远征仅沿用已保存且满足三个条件的队伍。
- 看不清消耗、页面不认识或出现未授权购买窗口时停止，本轮后续游戏任务也会跳过。已选商品只通过核对后的四家兑换商店窗口提交。后面的项目一起显示失败时，先看最前面失败任务的日志；修正后重新开始即可，不会自动重提已开始的竞技场代理。
- 每轮共用 20 分钟和 200 次操作上限；同一时间只允许一个助手控制游戏。
- 当前活动配置有效到 **2026-10-25 23:00（北京时间）**。换活动后需重新校准入口和关卡。

## 这次确实用了 Maa

界面是 [MXU 2.7.1](https://github.com/MistEO/MXU/releases/tag/v2.7.1)，执行和识别引擎是 [MaaFramework 5.14.3](https://github.com/MaaXYZ/MaaFramework/releases/tag/v5.14.3)。

MXU 读取 `app/interface.json` 生成任务卡片、参数、设备预览和日志，通过 Maa 任务器调用 Python Agent。游戏截图、点击、OCR 和图片模板匹配均走 MaaFramework。Python 中保留的是游戏流程、预算核对和停止保护；不再运行旧的 Tkinter 界面，也不使用 RapidOCR。

启动入口会先启动 MXU 所需的管理员宿主，再把专用 ADB 端口 **15037** 的环境设置传给界面，避免 MXU 自行重启后丢失设置。普通启动不预先检查 ADB、查找 adb.exe 或连接模拟器；窗口打开后由 MXU 搜索和连接，未找到设备或连接失败时仍可留在界面重试。连接环境使用 `ADB_SERVER_SOCKET=tcp:15037`，允许 MXU 在需要连接时自动启动本机 ADB 服务。只有「仅检查连接.bat」会先执行 ADB 诊断。不会重置 5037 端口。MuMu 地址当前是 `127.0.0.1:16384`。

## 文件在哪里

| 位置 | 内容 |
| --- | --- |
| `app` | MXU 界面、Maa 运行库、任务声明和识别资源 |
| `agent`、`cangwu` | 自定义任务、资源核对和停止保护的源代码 |
| `runtime/runs` | 本次运行的日志、截图、结果报告 |
| `runtime/latest_report.json` | 最近一条游戏任务的报告；不是整轮汇总 |
| `runtime/state` | 商店每日／每周累计、共鸣每周累计、未确认提交记录 |
| `docs/验证说明.md` | 检查方式、实测范围和暂未覆盖的分支 |
| `licenses`、`DEPENDENCIES.json` | 第三方许可、固定版本与校验值 |
| `苍雾世界.code-workspace` | 独立编辑器工作区入口 |

本项目使用根目录启动入口，旧版界面及本机历史记录不属于发布内容。第三方组件的来源和许可见 [第三方组件说明](THIRD_PARTY_NOTICES.md)。

## 开发与检查

本机私有环境在 `.venv`。如需重建，使用 64 位 Python 3.13 创建环境，再按 `requirements.txt` 安装；MXU 与 Maa 原生库版本及来源记录在 `DEPENDENCIES.json`。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools\validate_resources.py
.\.venv\Scripts\python.exe tools\setup_runtime.py --check
.\.venv\Scripts\python.exe tools\run_maa.py --tasks check
```

最后一条使用真实 Maa 控制器检查 MuMu。`tools/verify_replays.py` 和 `tools/verify_feature_replays.py` 为开发者本地截图回放工具，需要自行准备 `tests/fixtures`；账号原始截图未随仓库发布。单元检查不依赖这些截图。

`tools/mxu_feature_acceptance.py` 通过正在运行的 MXU 验证新功能，所有商店及扫荡场景均强制使用预览，不点击兑换确认或开始扫荡。界面的正式任务则按用户实际选择执行。若默认 HTTP 端口被其他程序占用，会在 MXU 的 12701～12710 范围内按项目路径查找本窗口；ADB 仍固定使用专用 15037。

不要直接双击 `app/mxu.exe`；使用根目录的启动入口，连接端口才会正确传给 MXU。修改或搬动项目路径后，需重建私有环境和启动快捷方式。
